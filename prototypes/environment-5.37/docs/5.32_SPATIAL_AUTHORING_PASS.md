# Ash & Aether 5.32 — Spatial Authoring 3D Pass

This pass attacks the current presentation failure mode directly: **valid game content that is spatially un-authored**. The game already has large inventories of terrain, vegetation, actors, encounters, bosses, equipment and environmental systems; the new layer makes those systems read as one designed place instead of independent objects scattered across broad planes.

## Implemented

- `scene-composer.mjs`: deterministic authored placement around meaningful anchors, connective landmarks between distant anchors, collision-aware local spacing, and automatic detection/repair of visually empty regions.
- `dungeon-director.mjs`: a seven-beat room grammar — approach, threshold, read, manipulate, encounter, aftermath, release — with eight manipulation forms and explicit visible before/during/after states.
- `music-continuity.mjs`: closes long dead-air gaps with adaptive bridges and crossfades instead of allowing ambience-only stretches to feel like missing music.
- `spatial-3d-integration.mjs`: a thin host adapter. It does **not** replace movement, terrain, encounter resolution, save ownership, inventory, or the audio engine.
- 4 new test files covering deterministic placement, empty-space repair, social clusters, visible dungeon state changes, music-gap repair and host delegation.

## Design rule

Every populated 3D scene should now contain:
1. **anchors** — doors, wells, machines, shrines, stalls, bridges, campfires, bosses, puzzle mechanisms;
2. **clusters** — actors and props placed because of those anchors;
3. **connectors** — readable landmarks and micro-events that visually join distant clusters;
4. **negative space with purpose** — combat lanes, sightline reveals, traversal breathing room, not accidental void;
5. **visible consequences** — environmental verbs change geometry/state in front of the player;
6. **audio continuity** — music can thin out, but should not simply disappear for tens of seconds.

## Integration target

Merge these modules into the source-owning Site session and bind the host callbacks to the actual Three.js scene, terrain masks, encounter state, save timeline and adaptive audio system.
