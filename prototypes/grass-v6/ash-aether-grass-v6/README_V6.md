# Ash & Aether / Living Grass v6 — 3D integration and performance handoff

**Checkpoint:** 2026-10-29. **Status: a versioned, runnable source package—not a deployed update to the private Ash & Aether Site.**

This is a continuation of v5. The source keeps all 16 plant families, 15 habitat distributions, deterministic ecology, timeline-specific persistence, idempotent harvesting, and both Canvas prototypes. It adds a Three.js host integration lab, terrain-normal fitting, camera-aware visibility, canopy shading, explicit build diagnostics, and camera-turn rebuild coalescing.

## Start here

- **Offline immediately:** open `cinematic-grass-offline.html` or `reconciliation-lab-offline.html`. These are self-contained Canvas2D reference scenes with the current v6 ecology and integration bridge bundled in. They are not the live game's actual camera or a true Three.js benchmark.
- **Real Three.js integration harness:** from this folder run `python -m http.server 8765` and open `http://localhost:8765/three-integration-lab.html`. The harness downloads pinned Three.js 0.180.0 from jsDelivr and imports the v6 `.mjs` modules locally. A browser with network and WebGL is needed. If startup fails, an error pane links to the offline labs. Never double-click the Three.js page from `file://`; browser module security will block the local source imports.
- **Run tests:** `node --test *.test.mjs` (57 passing source regression tests at packaging time; Node 18+).
- **CPU synthetic benchmark:** `node benchmark-field.mjs`. Its output is **not GPU performance** and cannot establish laptop/Android FPS.
- **Regenerate offline preview:** `python build-cinematic-lab.py && python build-offline-lab.py`.

## Production wiring

```js
import {createAAGameVegetationBridge} from './aa-game-integration.mjs';

// Adapt host-owned methods: do not add a second terrain or collision plane.
const vegetation = createAAGameVegetationBridge({
  THREE, scene: game.scene, renderMode: 'gpu', seed: game.worldSeed,
  timelineId: game.timeline.id, quality: userSettings.vegetationQuality,
  groundOptions: {
    materialAt: (x,z) => game.ground.materialAt(x,z),
    regionAt: (x,z) => game.world.regionAt(x,z),
    heightAt: (x,z) => game.world.heightAt(x,z),
    normalAt: (x,z) => game.world.normalAt(x,z), // optional
    pathAt: (x,z) => game.world.pathMaskAt(x,z),
    obstacleAt: (x,z) => game.world.isNonVegetated(x,z),
    shadeAt: (x,z) => game.world.canopyShadeAt(x,z),
    moistureAt: (x,z) => game.world.moistureAt(x,z),
    seasonAt: (x,z) => game.world.seasonAt(x,z),
    weatherAt: (x,z) => game.world.weatherAt(x,z),
  }
});
function frame(dt) {
  const direction = new THREE.Vector3(); game.camera.getWorldDirection(direction);
  vegetation.tick(dt, game.player.position, {
    worldDay: game.world.day,
    wind: game.world.wind,
    rain: game.world.rain,
    cameraView: {
      x: game.camera.position.x, z: game.camera.position.z,
      forwardX: direction.x, forwardZ: direction.z,
      nearRadius: 10, halfAngleDegrees: 75
    }
  });
}
// Only after the host commits its action and reward transaction:
// vegetation.applyEvent({type:'harvest',eventId: stableHostId,x,z});
// vegetation.notifyTerrainChanged() after terrain/path/building changes;
// vegetation.snapshot() belongs in the same authoritative save transaction;
// vegetation.dispose() on scene unload.
```

Do not copy the dummy Three.js terrain, river, building, avatar or trees from `three-integration-lab.html` into the game. They exist only to test terrain and camera integration against known host-like inputs.

## v6 changes

1. **Opt-in camera view selection.** `cameraView` can be set on bridge creation and on each `tick`. It conservatively preserves a full close ring and omits far plants behind the camera. Camera motion alone never changes terrain/gameplay sampling. Movement or rotation of less than 2m/12 degrees does not trigger a full rebuild; a 280ms cooldown coalesces larger changes.
2. **Host terrain normal fitting.** Optional `groundOptions.normalAt` adds per-instance slope data, shearing grass stems along the local terrain tangent for less floating on slopes. Normals are clamped and invalid normals fall back to level grass. No terrain mesh or collision shape is generated by the vegetation layer.
3. **Canopy shading.** The shader now uses a per-instance `aShade` value from the same ecology shade sampler as the host, rather than lighting every clump identically.
4. **Performance diagnostics.** `getStats().gpu` includes `buildMs`, `buildCount`, `viewRejected`, `allocatedInstances`, `cameraRebuildPending`, `plants`, `flowers` and nominal species draw-call count. The test harness also displays live `renderer.info.render.calls` / triangles and observed frame rate, *if* the browser renders.
5. **Fallbacks.** The original fully offline Canvas preview/lab still runs without three.js. Graphics detail changes never alter rules, inventory, rewards, AI, concealment, or timeline save state.

## Known limits and release gates

- **Not deployed to A&A.** The private Site only exposes a limited Library content projection and returns 401 to unauthenticated requests. No game source, exact deployed camera, or canonical map geometry was available in this session.
- **No actual GPU verification.** The sandbox Chromium environment returned no WebGL context, so shader compilation, final colors, shadows, draw calls and frame rate of the Three.js harness could not be validated. The live harness is a concrete test scene, not an already verified 3D render.
- **CPU tests use structural Three.js mocks.** Do not interpret their success as a GPU shader compile. `BENCHMARK_V6.json` contains host-specific single-run CPU results, not GPU or end-user FPS.
- **Ground Forge data still needs binding to its canonical registry.** The 48-material source is owned by the ground session, not duplicated here. Likewise, monsters, collision masks, Hydrophone audio and the player's renderer must be connected by the live game source owner.
- Compare camera poses in real gameplay, test interior/door/river/bridge exclusions, inspect slope root contact, run actual compiled shader and mobile memory/FPS checks, validate old saves and NG+ under the full host suite, and verify one harvest reward transaction per authoritative event ID before shipping.
- Test at target camera distances, not only the illustrative painterly perspective scene. High/detail mode and heavy buildings need real GPU timings, especially on Android.
